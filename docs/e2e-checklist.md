# V1 人工 E2E 验收清单（§37 九个 Case）

> 前置条件：一台装有 **Docker + Chromium 系统依赖** 的服务器（`docker compose build` 会用多阶段镜像构建）。
> 使用**测试抖音小号**，避免影响正式账号；`.env` 需配强 `ADMIN_PASSWORD` 与 ≥32 位 `SESSION_SECRET`，否则服务会 fail-fast 拒启。

## 启动
```bash
cp .env.example .env        # 填入 ADMIN_PASSWORD / SESSION_SECRET，可设 COOKIE_SECURE=true
docker compose up -d
curl -I http://127.0.0.1:8000/api/v1/system/health
```
预期：健康检查返回 `200`，后台可访问。

## Case 1 · 扫码登录
- 步骤：登录后台 → 抖音账号 → 新建/选择账号 → 扫码登录 → 手机抖音 App 扫码。
- 预期：二维码出现 → 扫码确认 → 提示「登录成功」，账号状态变「正常」。

## Case 2 · 刷新保持登录
- 步骤：登录成功后刷新页面（F5），重新进入账号页。
- 预期：无需重新扫码，登录态仍在（`state.json` 已保存）。
- 结果：`[ ] 通过  [ ] 未通过`

## Case 3 · 同步联系人
- 步骤：好友管理 → 选择账号 → 同步联系人。
- 预期：后台轮询结束，列表出现已有聊天联系人，含名称/火花天数。
- 结果：`[ ] 通过  [ ] 未通过`

## Case 4 · Dry Run 不发送
- 步骤：续火任务 → 勾选好友后点「Dry Run 测试」。
- 预期：返回成功/失败/原因，**不产生任何真实消息**，好友未收到消息。
- 结果：`[ ] 通过  [ ] 未通过`

## Case 5 · 手动发送
- 步骤：续火任务 → 立即执行（二次确认）。
- 预期：页面提示「任务已开始」，指定好友收到消息，日志记 `success`。
- 结果：`[ ] 通过  [ ] 未通过`

## Case 6 · 定时发送
- 步骤：配置 `执行时间` 与 `随机窗口`（如 21:00/30 分钟），保存并等待触发。
- 预期：在计划窗口内自动执行，无需手动触发。
- 结果：`[ ] 通过  [ ] 未通过`

## Case 7 · 重启 Docker 数据不丢
- 步骤：`docker compose down && docker compose up -d`。
- 预期：账号、勾选好友、任务配置、运行日志仍在（`./data` 挂载持久化）。
- 结果：`[ ] 通过  [ ] 未通过`

## Case 8 · Cookie 失效提示重新登录
- 步骤：手动删除账号 `state.json`（或等其过期），检测登录/发送一次。
- 预期：账号状态变「需重新登录」，不继续发送，后台明确提示重新扫码。
- 结果：`[ ] 通过  [ ] 未通过`

## Case 9 · 安全验证即停
- 步骤：触发抖音限流/安全验证（或出现「操作频繁/安全验证」提示）。
- 预期：本轮立即停止，`risk_detected` 置真，日志提示需人工处理，**不自动绕过验证**。
- 结果：`[ ] 通过  [ ] 未通过`

## 常见失败定位
- 扫码超时/无二维码：服务器网络不通抖音、容器内 Chromium 未装依赖、`shm_size` 过小而页面崩溃。
- 发送失败：抖音登录态过期、异地/机房 IP 风控、会话未切换（§18 校验拦截）。
- `docker compose up` 启动即退：`.env` 未配 `ADMIN_PASSWORD`/`SESSION_SECRET`，触发 fail-fast。
